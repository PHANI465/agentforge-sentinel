## R37 — connection ownership ends before every user of it has finished (high)

`src/sentinel/agents/budget.py:141-207` owns a SQL operation thread, an optional cancel
thread, and socket shutdown. Those three users are not coordinated through one lifetime.
Two independently gated counterexamples reproduce the unsafe ordering:

### A. A completed COMMIT leaves a canceller that can affect the next statement

At lines194-207, bounded_call may return a confirmed result while its cancel thread still
runs. The connection is neither retired nor quarantined in this path, so the coordinator
can reuse it. A late cancellation for COMMIT can instead hit the following transaction.

**Evidence on Windows and native Ubuntu:** a controlled commit returns a confirmed result
just after cancellation starts. The canceller is held by an Event. bounded_call returns,
QUARANTINE.holds(conn) is False, the caller changes the active operation to "next statement",
and releasing the old canceller records that it affects that next operation. This is an
injected cancel transport/connection stand-in, not a real PostgreSQL cancellation trace.
The actual production lifetime code is exercised and every test-owned thread is released.

### B. Socket shutdown can use a descriptor after its connection has closed

At lines161-171, an abandoned SQL worker closes the connection as soon as it returns.
Meanwhile lines201-203 call _shutdown_socket outside that ownership lock. The worker can
close the original descriptor after the shutdown wrapper borrowed it but before shutdown
uses it. The operating system may reuse the descriptor for a different connection.

**Native Linux evidence with real test-owned sockets:** the probe creates two socketpairs.
It gates the production wrapper after it borrows the original descriptor, releases the
late SQL worker to close the original, then duplicates the *probe's own* unrelated socket
into that freed descriptor using os.dup2. Production shutdown then affects this unrelated
socket: its peer receives EOF, while the unrelated socket's own owner is still open. This
is a forced valid interleaving, not a timing lottery; all descriptors belong to the probe.
No external socket/process/file is touched. The registry returns to zero afterwards.

**Required correction:** give SQL work, cancellation, shutdown, reuse and close one explicit
connection-lifetime owner. A connection must not be reusable, closed or removed from
outstanding-resource accounting until no outstanding canceller or shutdown borrower can
still act on it. Make shutdown/close descriptor ownership atomic or use a safely acquired
independent socket reference; a bare integer borrowed across a possible close is unsafe.

Keep the response wait finite. If cancellation outlives the response budget, retire the
connection and retain accounting rather than waiting indefinitely or reusing it. A known
COMMIT reply must retain its known meaning; retiring its connection must not fabricate
rollback/unknown state. Pending/unknown COMMIT semantics, recovery and provider leases
remain unchanged. Bound all helper ownership; do not accumulate detached cancellation or
cleanup workers without admission accounting.

Add failing-first, event-gated regressions for both interleavings, a positive safe-reuse
case after all helpers finish, exactly-once close and eventual accounting release. Use an
intercepted equivalent on Windows for the POSIX descriptor case; keep the existing single
allowed skip policy. Do not rely on sleeps or repeated successful stress runs as proof.
