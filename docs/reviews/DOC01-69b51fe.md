## R58 — unreadable live `/proc` member is counted as absent (blocking)

The new POSIX recovery correctly keeps a record when it can see a live member
after its leader exits. But `tools/document_worker/src/docworker/supervisor.py`
`_stat_fields()` (lines 233–240) converts **every** `OSError` reading
`/proc/<pid>/stat` to `None`; `group_members()` (lines 246–262) silently skips
that entry. An unreadable live member can therefore make `_group_empty()`
return `True`, letting `recover()` delete the record and run folder. The
protocol says an undeterminable group yields `group_state_unknown_kept`.

Independent native Ubuntu probe used a real session leader and sleeping group
member. After the leader exited, the probe injected `PermissionError` only
for the live member's `/proc/<pid>/stat` read. The real recovery path returned:

```json
{"report":"recovered","recovery_record_exists":false,"member_alive_after_recovery":true}
```

The probe restored the read method and stopped its own verified member by PID.
The same probe without the injected read fault returns
`group_members_alive_kept` with its record intact. Distinguish a genuinely
disappeared entry from permission/I/O/malformed data, and fail closed on
unknown group state. Verify that all failure paths preserve the recovery
record and owned run folder without signalling an unproved group.
