## R51 closed as a corrected measurement design

Whole-report units, query/control enumeration, joint platform selection, matched design
comparison and missing-evidence rules address the prior review. One remaining stage
calculation still assumed a connection was bounded by 2 s despite explicitly denying that
guarantee. A last operation at 2299 s with an allowed 200 s stalled connection, 10 s report
work and 300 s cleanup could reach 2809 s, beyond 2700. This is arithmetic, not observed
network performance.

The integrated spec now requires a 2350 s independent whole-stage work/wait deadline,
300 s cleanup reserve and 2650 s controller wait limit inside the unchanged 2700 s outer
cap. The controller must cover blocked acquisition/setup as well as report SQL. It must
verify owned resource termination or fail with recovery and no further stages. Command
allowance totals are planning estimates; unconfirmed cleanup has no claimed completion
bound. No full-size or ten-hour measurement job is assigned by this acceptance.

## R52 closed as a corrected resource/control design

Connection acquisition is honestly outside report B. Report-specific rollback reserve,
independent registry, feasible refusal/submission controls and outcome meanings are sound
design requirements, still unimplemented in production.

The remaining admission rule was insufficient: with 1 retired connection, separate
active<M and retired<Q checks admit 2 operations; if both retire, the registry reaches 3
despite Q = 2. Atomic checks alone do not fix that. The integrated design reserves one
resource slot before connection, transfers its ownership on retirement and releases it
only on definitive acquisition failure or actual final close. Retired resources can
therefore never exceed reserved capacity Q. Coordinator admission M is counted separately.

The original C4 also assumed three withheld-reply runs fill Q. Socket shutdown can make
their workers drain immediately; with two genuinely held slots a third request must
already refuse. C4 now checks real relay no-reply retirement/drain. Separate C5 injects
a controlled final-close delay, holds 2 actual leases, proves third-admission refusal
before connect, then releases/drains and verifies a fresh request. It is labelled fault
injection, never real cancellation latency. Production/workflow socket shutdown is retained.

Independent arithmetic state exploration confirms the reservation invariant for all
reachable abstract states in the model. That is a design check, not functional proof of
an unimplemented controller. M1's small real-database/unit tests must prove the actual code.
