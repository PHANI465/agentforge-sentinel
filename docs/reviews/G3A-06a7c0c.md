## R31: bound capacity across late-running calls (high; design blocker)

At candidate `docs/agents/G3A-design.md:77-81,159-168`, a process semaphore limits live
workflows and a timed-out role may repeat. The reused helper at
`src/sentinel/service.py:531-546` returns on timeout and calls `shutdown(wait=False)`;
the old worker can still run. The proposal does not define semaphore release while that
worker is unresolved. Releasing it when the HTTP workflow ends lets successive requests
accumulate late workers despite the advertised concurrency protection. Repeating inside
one workflow can also overlap calls.

Specify who owns an admission lease, when it is released on each failure/crash path, and
how unresolved calls count against a process-wide outstanding-call bound. A conservative
first slice may retain capacity until the worker actually completes and refuse repeats
while it remains unresolved. Do not claim thread cancellation or cancellation of provider
billing. The 150-second response deadline must cover tools and coordinator work too:
include remaining-deadline checks and bounded database/tool waits. A request deadline and
a pending-worker lifetime are separate quantities.

Add design examples for timeout -> late completion -> another admission attempt, and
for deadline exhaustion in gathering; specify expected records, refusal and release.
Implementation tests belong to G3B, not today's documentation task.

## R32: terminal workflow state cannot depend on a running role (medium; design blocker)

At candidate `docs/agents/G3A-design.md:93,157-164,202-205`, inconclusive completion uses
`_fail_run` and recovery fails the running role, while gathering happens before any role
run and a crash may happen between roles. Existing `_fail_run` requires an AgentRun;
there may be none at all, or only completed roles that must retain their true status.
The promise that the last run is always inconclusive is therefore not universally valid.

Define a workflow-level terminal transaction independent of an active role: scope, case
revision/workflow guards, terminal code/time, case reopening, and audit principal. Fail
an actual running role when present; preserve completed role records; do not invent or
rewrite a role run to make HTTP output convenient. Specify CaseDetail for zero-role and
between-role failures. State which completed investigator run is eligible as basis for an
abstention intent; if none exists, finish inconclusive with no intent. Add explicit examples
for before-first-role exhaustion and between-role recovery. No new HTTP route is needed.

examples already supplied; it does not establish these invariants.
