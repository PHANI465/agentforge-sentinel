## R21 [P1]: Vite shutdown does not establish the exact owned process

Locations: web/e2e/global-teardown.ts:152-153; web/e2e/support/serve.mjs:42-45, 37-40, 117.

Global teardown accepts any live PID whose current command line contains vite.js. runtime.json records only a PID, without process creation identity or an exact expected executable/script/run identity. A stale/reused PID for a Vite process in another workspace passes this guard and receives taskkill /PID ... /T /F. The server wrapper also calls taskkill from its stored child PID unconditionally, including after the exit event, and ignores the stop helper's outcome.

Independent exact-source, bundled/intercepted probe supplied a synthetic recorded PID whose command line named E:/ANOTHER-WORKSPACE/node_modules/vite/bin/vite.js. The unmodified teardown attempted taskkill for it. Every process command was intercepted; no real process was killed. Reproducer: E:/PHANI/Interview/tmp/u02_7190_review_probe.cjs.

Correction: establish exact run ownership and process creation identity, compare the expected executable/script/worktree as relevant, and refuse termination if identity is stale, unavailable or different. Already-exited children must not be killed by a recycled PID. Treat stop/termination failure as failure and preserve recovery metadata; do not report successful cleanup merely from an ignored exit code. Keep C02's reviewed lifecycle helper unchanged unless a specific backend change is separately requested.

Acceptance: intercepted regressions for reused PID/foreign Vite, missing identity, already-exited child and failed stop, plus actual owned-process cleanup on success and on a failed browser run. No live foreign process may be terminated to prove the bug.

## R22 [P2]: credential scan can pass without checking the credential or artifact subtree

Locations: global-teardown.ts:81-87, 129-147, 155-163; scan-artifacts.mjs:21-45; workbench.pw.ts:491-505.

If the server wrapper already stopped the stack and deleted its manifest, secretsFrom returns []. Teardown treats a missing manifest as successful shutdown and scans without any token values. In the safe probe a plain synthetic bearer canary was present in an ordinary error-context.md, the token set was empty, and teardown nevertheless reported a passing scan. The generic DSN pattern does not detect a bare bearer value.

Separately, scanTree skips every directory named stacks or starting sentinel-browser-, even inside test-results. Broad name-based exclusions must not stand in for an exact owned private-state exclusion. Read/scan errors also currently disappear into a clean result.

The final test attaches a hand-written snapshot named deliberate-failure but itself succeeds. The scanner self-test plants text files; neither is the required real failed Playwright artifact/report/teardown path.

Correction: retain the needed expected secret set until verification completes, or fail explicitly when it is unavailable; verify current-run ownership rather than trusting stale runtime state. Exclude only the exact private fixture state deliberately allowed by the policy, and fail closed on unreadable/unknown scan inputs. Scan all intended artifact paths after their writers finish. Add an actual intentional browser failure handled as a verification probe, checking its real artifacts and teardown without leaking token values into output. Keep tracing/video/sensitive captures off unless complete redaction is verified.

Acceptance: genuine raw-canary detection with the manifest absent/cleanup reordered; artifacts in a directory named stacks are scanned; scanner read failures cannot report clean; real post-login failure produces sanitized artifacts and exact owned-resource cleanup.
