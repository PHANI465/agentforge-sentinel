## R28 - High: startup does not fail closed before identity or after readiness timeout

Two paths in scripts/local_stack.py:start_api still break the recovery/readiness contract:

1. At lines 449-454, identity(process.pid) is called after Popen but before saving any pending API record. If inspection raises StackError (or returns None while an interpreter child survives), up fails with no PID/port recovery state. A later down sees api=None, reports success and can stop the database despite the unaccounted-for launch.
2. At lines 459-466, wait_until(ready, READY_SECONDS) is ignored. After a false timeout, a live process with an owned listening port is sufficient to return "API up", even with no successful /healthz response. An owned TCP listener is not proof that the API is ready.

No real process was spawned/killed and no database connection was made in these probes.

Refuse down/database stop while an unresolved launch could still be alive, until its exit and relevant port closure are proved. Never kill an unverified PID. Startup success must require a successful health response within the readiness policy and verified owned process/listener. On timeout follow verified cleanup or retain recovery and return nonzero.
