# Invited Sentinel pilot

The owner selected an invited pilot using synthetic files and official public
reports on November 16, 2026. Start with three to five reviewers and one
facilitated session per reviewer. Use the purchasing sample, a normal control
and an unfamiliar public report. Each session takes about 20 minutes.

## Invite and prepare

Send each reviewer an individual invitation to a scheduled session. For a
browser-only exercise, the facilitator may share the public tool and ask
reviewers to use the provided examples. For an access-restricted trial,
distribute the reviewed static bundle privately and serve it on loopback using
the README command. Use a fresh browser profile without third-party extensions
where possible. Any live workbench demo uses the existing synthetic guest
service.

The invitation should name the exact files, the purpose of the session and
what feedback will be collected. Ask reviewers to use only the supplied
synthetic files and official reports. Keep file sources and SHA-256 hashes
with the run, and report corrections to the facilitator.

## Run the session

1. Open the invoice, order and delivery together. Ask the reviewer to find the
   price and quantity issues, then trace each one to the cited record.
2. Open the matching control. Ask which checks are supported and which
   inputs still need verification.
3. Review the provided official report. Compare the exact amounts, currency
   and period against a publisher reference prepared before the session.
4. Show the live synthetic case or recorded case walkthrough. Ask who can
   approve, when execution becomes available and what the audit proves.
5. Record elapsed task time, completion, source verification, confusion,
   false alarms and intended interpretation. Use a reviewer code on the
   result form. Keep invite contact information separate.

Record refused, unreadable and inconclusive outcomes alongside matches. Count
known fields as correct, incorrect or missing. An assessment of fraud
precision needs separately labeled discrepancies and normal controls.

## Review and acknowledge limitations

Provide a 30-day retention window for pilot notes. Delete the participant
contact list and raw notes afterward and record the deletion. Keep only
anonymous totals and product issues needed for follow-up. Browser file review
uses tab memory, while hosted synthetic sessions have their own retention
policy. If a participant accidentally selects private data, stop the exercise
and clear the tab. Follow the facilitator's incident process for any private
data shared outside the tab.

Before expanding beyond this pilot, establish named sign-in and revocation,
tenant boundary tests, an approved retention and backup-deletion process,
and measurable service limits. Server-side customer uploads additionally need
an isolated parser and durable job admission. The pilot works with public or
synthetic data using the existing browser boundary.
