## Implemented

- **Contract (candidate 386b0af, unchanged shapes):**
  - domain v1 is additive (`uncalibrated_score`, optional `ScoringOutcome.model` / `inputs`, omitted when absent);
  - HTTP v1.1 adds `GET /v1/scoring` and `GET /v1/model-results/{id}` (`p1` only);
  - legacy `openapi.v1.json` is frozen by hash, and the 21 v1 examples are byte-identical.

  This increment adds four model-mode examples and the `422 account_profile_missing` code; `openapi.v1.1.json` is unchanged by it.
- **Scorer:**
  - the rule is the default;
  - `SENTINEL_SCORER=model:hgb_balanced@p1` loads only the registry entry, with protocol, selection and manifest identity bound before `load_trusted` deserializes;
  - an unknown value or failed binding stops startup; there is no fallback.
- **Decision-time f1:**
  - `Sentinel._model_score` calls C03's `data_pipeline.features.compute` at the decision key `(now, external_id)`, under the existing per-account lock;
  - history: scope rows with `occurred_at` in [t-30d, t) ingested before the key;
  - `prior_known_fraud`: fraud disclosures with `disclosed_at <= now`, excluding the transaction itself;
  - the frozen pointwise threshold 4.0295386895426815e-06 is used (not top-15);
  - numpy is imported only in model mode.
- **Authoritative inputs:**
  - migration 0004 adds `account_profiles` and `fraud_disclosures`, both scoped by tenant and session;
  - `sentinel.cli provision-accounts` / `record-disclosures` load them (operator only; no HTTP route);
  - the runtime role has SELECT only on both.

  A missing profile returns 422 with nothing stored and no defaults.
- **Persisted outcomes:** a model outcome stores `model` provenance and `inputs` (f1 values, currency, history rows, disclosures used, profile fields). Replays return the stored record across restarts and scorer switches, and cases pin `hgb_balanced`.
- **Packaging:** the wheel ships `sentinel`, `ml` and `data_pipeline` with only the p1 identity, artifact and results files, plus migrations 0001–0004.
- **Decision record:** 0006, proposed. It covers why disclosures store `account_id`, and the rejected alternatives: derived profiles, rule fallback, online top-k and a provisioning route.

## Not verified / gaps

- **Not measured:**
  - model-mode latency or throughput;
  - alert volume (the frozen threshold is very low, and both smoke transactions alerted);
  - memory footprint of the loaded pipeline beyond the 284 KB artifact directory.
- **Profiles:** there is no staleness policy, since profiles are trusted as provisioned. Disclosures are append-only with no correction or retraction flow.
- **CLI input validation:** the CLI loaders take JSONL without a schema beyond DB constraints.
- **Platforms and integration:** not tested on Linux/macOS or in CI; no browser/U03 integration (Cursor's work, after Codex accepts the contract); no live Claude.
- **Wheel:** installs top-level `ml` and `data_pipeline` packages, which could collide with other distributions of those names in a shared environment.
