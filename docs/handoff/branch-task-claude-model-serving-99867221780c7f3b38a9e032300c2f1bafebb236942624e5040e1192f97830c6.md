## R23 fix (this commit)

- **Problem (review R23):** operator profile and disclosure writes committed on independent connections without ingestion's account lock. A write committed after a model decision captured T could still enter that decision's features.
- **Fix:**
  - **Shared lock** (`src/sentinel/service.py`): new `Sentinel._lock_accounts` takes the scoped per-account advisory lock(s), using the key ingestion already used, deduplicated and in ascending key order. Ingestion, `provision_accounts` and `record_disclosures` all use it.
  - **Times after locks:** the writers now read their stamp time only after all their locks are held. They used to read it before connecting.
  - **Disclosure availability:** the model's disclosure query also requires `recorded_at <= now`.
  - **Profiles:** no timestamp predicate, so an earlier valid profile is never lost; the lock keeps updates out of an in-flight decision.
  - **Batch cap:** a batch may lock at most 256 distinct accounts (`batch_too_large`, checked before any lock or write). `sentinel.cli` loads in chunks of that size, one transaction each, and reports progress.
- **Validator follow-up** (`src/sentinel/contracts/v1.py`): a rule outcome carrying only `model` or only `inputs` is now rejected. The exported schemas and all examples are byte-unchanged (export checks pass).
- **Tests** (`tests/test_c07_r23_decision_boundary.py`):
  - real connections and commits; gates are events at the exact clock read or before `_model_score`;
  - lock waits are observed in `pg_locks` with bounded polling, and thread failures propagate via futures;
  - no sleeps decide success, and no HTTP test routes are used.

  | Test | What it proves |
  | --- | --- |
  | `test_write_committed_after_decision_time_does_not_enter_it[disclosure, profile_update, new_profile]` | Scoring first: ingest is paused after T while the operator write runs. The write waits for the decision, and its stamp is read after the lock (the clock moved from T+1 to T+3 while it waited; T+3 is stored). The decision at T sees only the earlier USD profile and the one disclosure recorded before T, or for a new profile is refused with 422 and stores nothing. A later decision includes the write. The stored decision replays unchanged. |
  | `test_decision_waits_for_an_inflight_write_and_then_includes_it[...]` | Writer first: the writer is paused at its stamp read while holding its locks. The decision waits, then includes the write. |
  | `test_disclosure_recorded_after_decision_time_is_unavailable` | A disclosure backdated but recorded after T (operator clock ahead) does not count at T, and counts later. |
  | `test_future_disclosed_at_stays_excluded` | Future-dated disclosures stay excluded. |
  | `test_another_sessions_write_does_not_wait_for_this_decision` | Session isolation: another session's write completes while this decision is paused, with no lock waiter. |
  | `test_batches_lock_accounts_in_one_global_order`, `test_overlapping_batches_serialize_without_deadlock` | Lock order is identical for any input order or duplicates. Opposite-order overlapping batches serialize without deadlock, and the last writer wins. |
  | `test_oversized_batch_is_refused_before_any_lock_or_write` | The 256-account cap is enforced before any lock or write. |
  | `test_rule_outcome_with_partial_model_payload_is_rejected[model, inputs]` | Partial rule payloads are rejected. |

## Implemented

- **Contract (candidate 386b0af, unchanged shapes):**
  - domain v1 is additive (`uncalibrated_score`, optional `ScoringOutcome.model` / `inputs`, omitted when absent);
  - HTTP v1.1 adds `GET /v1/scoring` and `GET /v1/model-results/{id}` (`p1` only);
  - legacy `openapi.v1.json` is frozen by hash, and the 21 v1 examples are byte-identical.

  This increment adds four model-mode examples and the `422 account_profile_missing` code; `openapi.v1.1.json` is unchanged by it.
- **Scorer:**
  - the rule is the default;
  - `SENTINEL_SCORER=model:hgb_balanced@p1` loads only the registry entry, with protocol, selection and manifest identity bound before `load_trusted` deserializes;
  - an unknown value or failed binding stops startup; there is no fallback.
- **Decision-time f1:**
  - `Sentinel._model_score` calls C03's `data_pipeline.features.compute` at the decision key `(now, external_id)`, under the existing per-account lock;
  - history: scope rows with `occurred_at` in [t-30d, t) ingested before the key;
  - `prior_known_fraud`: fraud disclosures with `disclosed_at <= now`, excluding the transaction itself;
  - the frozen pointwise threshold 4.0295386895426815e-06 is used (not top-15);
  - numpy is imported only in model mode.
- **Authoritative inputs:**
  - migration 0004 adds `account_profiles` and `fraud_disclosures`, both scoped by tenant and session;
  - `sentinel.cli provision-accounts` / `record-disclosures` load them (operator only; no HTTP route);
  - the runtime role has SELECT only on both.

  A missing profile returns 422 with nothing stored and no defaults.
- **Persisted outcomes:** a model outcome stores `model` provenance and `inputs` (f1 values, currency, history rows, disclosures used, profile fields). Replays return the stored record across restarts and scorer switches, and cases pin `hgb_balanced`.
- **Packaging:** the wheel ships `sentinel`, `ml` and `data_pipeline` with only the p1 identity, artifact and results files, plus migrations 0001–0004.
- **Decision record:** 0006, proposed. It covers why disclosures store `account_id`, and the rejected alternatives: derived profiles, rule fallback, online top-k and a provisioning route.

## Not verified / gaps

- **Not measured:**
  - model-mode latency or throughput;
  - alert volume (the frozen threshold is very low, and both smoke transactions alerted);
  - memory footprint of the loaded pipeline beyond the 284 KB artifact directory.
- **Profiles:** there is no staleness policy, since profiles are trusted as provisioned. Disclosures are append-only with no correction or retraction flow. R23 does not change this.
- **R23 limits:**
  - Direct owner SQL bypasses the lock boundary.
  - Stamps assume synchronized API and operator clocks.
  - Lock contention from large batches was not measured.
  - Deadlock-freedom rests on the single global lock order. It is tested by order equality and by one forced overlapping-batch interleaving, not by exhaustive interleavings.
- **CLI input validation:** the CLI loaders take JSONL without a schema beyond DB constraints.
- **Platforms and integration:** not tested on Linux/macOS or in CI; no browser/U03 integration (Cursor's work, after Codex accepts the contract); no live Claude.
- **Wheel:** installs top-level `ml` and `data_pipeline` packages, which could collide with other distributions of those names in a shared environment.
