## Implemented

- `GET /v1/cases/{case_id}/investigation-trace[?workflow_id=]` returns `InvestigationTrace`.
  It reads one REPEATABLE READ READ ONLY transaction scoped to tenant and session, and it
  never recovers, runs or writes anything.
- Selection:
  - order by `case_revision` DESC, which is strictly increasing per case; ties on
    `started_at` cannot reorder;
  - the default is the newest workflow, and `workflow_id` selects any workflow of the case;
  - the listing is capped at 25, with `workflow_count`.
- Honest states:
  - no workflow, or legacy single-investigator runs (counted, not invented);
  - running, with null counters and `deadline_status` before_deadline, past_deadline or
    recovery_due;
  - recovered;
  - zero attempts;
  - failure source `role_step` or `workflow_terminal`;
  - usage null when unrecorded, with attempts distinguished from provider calls;
  - `limits` only when the server's config digest matches.
- v1.1 OpenAPI is now frozen by SHA-256 (`V11_SHA256`), like legacy v1, and v1.2 is the active
  snapshot. The v1 and v1.1 example runs are unchanged. The exporter's UUID prefix is
  per-run, with the default unchanged.
