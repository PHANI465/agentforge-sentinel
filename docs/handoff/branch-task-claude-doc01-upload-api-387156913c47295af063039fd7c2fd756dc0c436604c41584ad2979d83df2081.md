## Implemented

1. **Pre-API worker correction** (`f9fce13`, `39f6df4`): the Windows `_write_record` /
   `os.replace` sharing conflict.
   - **Reproduced first:** 6 failing tests at 0dd848e. With a real open reader handle,
     cleanup raised `WinError 32` out of `extract`, which crashed the supervising process.
     A failed replace left an orphan `r_*.tmp`. A pid stored only in a `.tmp` was
     "recovered" without being stopped.
   - **Fix:** unique temporary names and a 2 s retry for transient `PermissionError`.
   - A record write failure is now `error` with `recovery_record_write_failed:<state>`,
     never a success.
   - A temporary is kept only when it carries a pid, and cleanup never raises.
   - Recovery treats temporaries as evidence. It reports `temporary_record_unreadable_kept`
     and `orphan_temporary_removed`.
   - This supports, but does not prove, the explanation for the historical intermittent
     crash-test failure.
2. **Worker bridge** (`31382f2`, `8b642d6`): `docworker.bridge`, protocol
   `sentinel.doc01.bridge/0.1`, handling one stdio request per process. Its operations are
   `status`, `ingest`, `analyze`, `records`, `delete` and `recover`.
   - The size and framing of the bytes are checked, then the content (PDF / ZIP / UTF-8
     text, OLE refused) before a handle is issued.
   - The full result is persisted beside the handle under the same owner.
   - It returns a compact view: records are paged (at most 500 and 2 MiB); page and
     narrative text are dropped; duplicate-group evidence lists are capped with totals.
3. **Contract freeze before any route** (`7ec6d24`):
   - decision 0010 (DOC01 owns v1.3, and AN01's provisional label moves to v1.4 or later);
   - the API document;
   - the `http_v13` DTOs and a projection of the worker result onto them;
   - real bridge answers recorded for 14 fixtures;
   - 31 `examples-v1.3` files built only from DTOs and recorded answers.
4. **API** (`1754128`):
   - **Routes:** `POST /v1/documents?format=` (raw bytes; octet-stream or format media
     type; streamed 10 MiB cap; no multipart, no filename), `POST …/{handle}/analysis`,
     `GET …/{handle}/records` and `DELETE …/{handle}`.
   - **Authority:** the opt-in `analyze_document` capability, also available as
     `sentinel create-session --with-document-analysis`. The four default grants are
     unchanged. A session without it gets 403; a missing, foreign, tampered, malformed or
     expired handle gets an identical 404.
   - **`sentinel.documents`:**
     - starts the registered interpreter (`SENTINEL_DOC_WORKER_PYTHON`, `SENTINEL_DOC_STORE`,
       optional source pin) with a minimal environment, cwd set to the store, stdout capped
       at 8 MiB and wall-clock bounds;
     - derives a per-session owner key, so the token never reaches the worker;
     - runs one analysis at a time;
     - marks *recovery pending* after a timeout, crash, invalid answer or unconfirmed stop,
       and refuses analyses with 503 until a recovery pass keeps nothing;
     - otherwise fails closed: 503, 502 or 504 respectively.
   - **Versions:** v1.2 is frozen by SHA-256 (`b52f8fd4…`); v1.3 is active (`d4306c65…`).
5. **Real-process check** (`4f59b57`, `26897f5`, `cd8f0f4`): `scripts/doc01_api_e2e.py` runs
   a disposable Postgres cluster, a real `uvicorn` API and the real locked worker.
6. **DEMO01 capture refresh** (`a9808ce`, `5d0f0da`, `bbc2bb6`); see "Coordination".

## Not verified / gaps

- **Fake bridge in the app gate.** The app gate uses the fake bridge; the real worker is
  exercised only by `doc01_api_e2e.py` (run explicitly). The real-worker timeout and
  POSIX-orphan recovery path through the API is exercised only with the fake (`hang`), not
  with a real hung parser.
- **Per-process state.** Busy and recovery-pending state is per API process. Two API
  processes sharing one store are not coordinated.
- **No quotas.** There is no per-session upload or handle quota; disk use is bounded only
  by the 10 MiB cap and the one-hour lease. Expired handles are purged only during
  recovery passes, not periodically.
- **Weak Windows process check.** The Windows "no worker processes left" e2e check reads
  `tasklist` window titles; the empty run, record and recovery directories are the
  stronger proof. The native check uses `pgrep`.
- **Not claimed:** UI, hosting, private files, OS isolation, OCR, PDF tables, LLM
  narrative, measured throughput.
- **Final checks:** the exact final-commit gates are reported in chat.
