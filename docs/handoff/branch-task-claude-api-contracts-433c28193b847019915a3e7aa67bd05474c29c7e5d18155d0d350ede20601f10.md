## Implemented

- **Response DTOs** (`sentinel.contracts.http_v1`): ErrorResponse, IngestResponse, CaseDetail (now also carries the recorded `scoring`), AgentRunView, IntentView, CaseSummary/CasePage, SessionView, Overview, ExecuteResponse, Health. They are wired as FastAPI `response_model`s, so responses are validated against the contract. Datetimes are normalized to UTC.
- **`GET /v1/cases`:**
  - session-scoped, keyset-paginated (`created_at` DESC, `id` DESC), opaque base64url cursor (at most 200 characters, validated: `invalid_cursor`);
  - `limit` 1–100 (default 25) and a `state` filter;
  - migration 0003 adds `cases.created_at` (backfilled from the body) and two indexes.
- **`GET /v1/session`:** scope, actor, sorted capabilities and expiry. No token, credentials or account data.
- **`GET /v1/overview`:** per-state case counts (all states present), transaction/alert/action totals, investigator name/version. Session-scoped.
- **Safe errors:** unknown routes give `{"error":"not_found"}` and wrong methods give 405 `{"error":"method_not_allowed"}`; query/path validation gives `invalid_request` with no echo.
- **OpenAPI 3.1 snapshot:** typed 2xx and error responses, request bodies (validated manually but now declared), and a bearer security scheme.
- **Frozen examples:** 21 request/response pairs from a deterministic run (fixed clock, sequential UUIDs). The run covers ingest (below threshold, replay, alert), pagination and filter, investigate, approve, execute and replay, the closed detail, audit, the expiry/reopen lifecycle, overview, session and 5 safe errors.
- **`record_approval`:** decision/expiry times are read after the case lock, so a delayed request cannot return an already-expired approval.
- **docs/api/README.md:** endpoints, auth/scope, pagination, score semantics (heuristic, not a probability; null = unknown legacy), workflow semantics (revision, current intent, expiry, idempotency, failure) and the status/error table.

## Review correction: R9 and R10 (on top of 0a6fb0e)

Changed paths: src/sentinel/service.py (`decode_cursor`), src/sentinel/contracts/http_v1.py (ErrorResponse description), contracts/http/openapi.v1.json (that description only; the 21 examples are byte-unchanged), docs/api/README.md (error contract scope and a client-fallback section), tests/test_c01_review_regressions.py (new), this note.

- **R9:** `decode_cursor` now requires the decoded JSON to be exactly a two-element list of strings before parsing. Then it requires a timezone-aware ISO timestamp and a valid UUID string. Every malformed input raises `ServiceError("invalid_cursor", 422)`. There is no blanket catch: only `ValueError`/`binascii.Error` from decoding and parsing are mapped. The fix also closes a case the review did not list: a JSON **object** whose two keys were a timestamp and a UUID used to unpack into a valid cursor (200).
- **R10 (bounded correction):** the contract now promises `ErrorResponse` JSON only for handled errors. The README documents that unexpected exceptions return a plain-text 500 (internals not echoed), and that proxies or networks can give non-JSON, empty or invalid bodies, or nothing at all. Clients must use a generic message and treat these as outcome unknown, re-reading state. After an ambiguous `POST /v1/actions` failure they must retry with the same `idempotency_key`; only a handled 4xx/409 is a definite outcome. There is no new JSON 500 handler; safe unexpected-error logging stays in C05.
