# 0008: Read-only investigation trace contract (HTTP v1.2, G3C-A)

- Status: proposed (candidate for Codex review; not accepted)
- Date: 2026-11-01
- Decided by: pending Codex review; proposed by Claude Code

## Context

G3A drafted `GET /v1/cases/{id}/investigation-trace` returning the agents-1.0 `TraceSummary`
(G3A-design §8). The persisted G3B records (migration 0005) show that this shape cannot
express several states honestly:

- It requires a workflow, so it cannot show a case with none, or a legacy
  single-investigator run.
- A running workflow's stored body still has its start-time counters (0). Serving them
  presents an unrecorded count as zero.
- It has no failure source, worker resolution, usage, timestamps, step order, basis run,
  prior-workflow index or deadline status.
- Analyst claim checks are not persisted, so `TraceRole.checks` would have to be
  recomputed.
- `tool_results` is capped at 12. Denied results are additional to the at most 12 executed
  calls, so 12 can be too few.

## Decision

1. **A new v1.2 HTTP DTO (`InvestigationTrace`), not `TraceSummary`.**
   - It reuses the frozen agents-1.0 nested models unchanged. `TraceSummary` and every
     agents-1.0 schema and example stay as they are.
   - The full shape and its semantics are in
     [investigation-trace-v1.2.md](../api/investigation-trace-v1.2.md).
2. **Selection and order:**
   - Workflows are ordered by `case_revision`, newest first. It is strictly increasing per
     case because each claim is a compare-and-set from `open`, so `started_at` ties cannot
     reorder them.
   - The default is the newest workflow, and `?workflow_id=` selects any workflow of the
     case. The listing is capped at 25 with a total count. There is no other pagination.
3. **One `REPEATABLE READ READ ONLY` transaction per read.** It gives one snapshot, and the
   database refuses writes. The GET never recovers a workflow. Overdue workflows are
   reported as `recovery_due` and stay running.
4. **Unknown is null:**
   - running counters are null;
   - usage is null without a `role_completed` step;
   - `limits` is null unless this server's config has the stored digest.

   Attempts are recorded role attempts, not provider calls.
5. **v1.1 is frozen by SHA-256**, like legacy v1, and `openapi.v1.2.json` is the active
   snapshot. The v1 and v1.1 example sets are still regenerated byte-identically. The
   exporter's UUID sequence takes a per-run prefix (default unchanged) so that the v1.2 run
   cannot collide with earlier runs on the shared example database.

## Consequences

- G3B code, migrations, grants, budgets and the R34-R37 semantics are unchanged. The
  projection is a separate module (`sentinel.trace`).
- Two existing checks that compared the live schema with v1.1 now compare it with v1.2, and
  check v1.1 by hash instead:
  - `tests/test_http_contract.py::test_openapi_snapshot_is_current`;
  - `tests/test_http_contract_v11.py::test_v11_snapshot_is_frozen`.

  No other assertion changed.
- Persisting analyst claim checks, or a stored `submitted` flag for provider calls, would
  need a G3B change and a migration. Neither is part of this decision.
